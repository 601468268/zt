四、核心代码与错误处理说明
4-1不同方法的 fetch 写法
// GET：直接把参数拼在地址上，不需要 body fetch('https://jsonplaceholder.typicode.com/posts?_limit=3') .then(res => res.json()).then(data => console.log(data)); // POST：method 改成 POST，用 body 带 JSON，并声明 Content-Type fetch('https://jsonplaceholder.typicode.com/posts', { method: 'POST', headers: { 'Content-Type': 'application/json' }, body: JSON.stringify({ title: '张涛的测试标题', body: '内容', userId: 1 }) }).then(res => res.json()).then(data => console.log('新建成功，id =', data.id)); // PUT / PATCH：地址要带 id；PUT 整体替换，PATCH 只改部分字段 fetch('https://jsonplaceholder.typicode.com/posts/1', { method: 'PUT', ... }); fetch('https://jsonplaceholder.typicode.com/posts/1', { method: 'PATCH', ... }); // DELETE：只写 method，没有 body fetch('https://jsonplaceholder.typicode.com/posts/1', { method: 'DELETE' });
4-2常见错误与提示
404 Not Found地址路径写错，或这个 id 的资源不存在
400 / 422请求体格式不对，后端校验没通过
401 / 403没带 token，或没有访问权限
500 / 502服务器内部错误，不是前端的问题
TypeError: Failed to fetch域名不通、被跨域（CORS）拦截、或页面是 https 而接口是 http（混合内容被浏览器阻止）
AbortError超过 15 秒仍未响应，前端主动取消（超时）
注意：fetch 只有在网络层失败时才走 catch，404 / 500 这类 HTTP 错误码是"请求成功返回"， 必须自己判断 res.ok 或 res.status，否则会把错误数据当成正常数据处理。
