做饭的流程本身就是"异步"的：买原料 → 取原料 → 同时和面、和馅（并行）→ 两个都完成后包饺子 → 吃饺子。 本页用 setTimeout 包成 Promise 来模拟每一步的耗时， 用 await 让有先后顺序的步骤串行执行， 用 Promise.all 让和面、和馅同时进行，最后用 try / catch 处理失败。 每个节点的耗时、状态和总用时都会实时显示在页面上。

二、核心代码（Promise + async/await + Promise.all）
2-1把 setTimeout 包成 Promise
// 等待指定毫秒后 resolve，这样就能用 await 等待 function zt_wait(zt_ms) { return new Promise(function (resolve) { setTimeout(resolve, zt_ms); }); }
2-2串行用 await，并行用 Promise.all
async function zt_makeDumplings() { try { // ① 有先后顺序：一步一步 await await zt_step('买原料', 6000); await zt_step('取原料', 2000); // ② 可以同时做的事：同时发起，用 Promise.all 等两个都完成 await Promise.all([ zt_step('和面', 4000), zt_step('和馅', 3000) ]); // ③ 再回到串行：包饺子 → 吃饺子 await zt_step('包饺子', 5000); await zt_step('吃饺子', 2000); console.log('全部完成'); } catch (zt_err) { // 任何一步 reject 都会跳到这里，后面的步骤不再执行 console.error('失败了：' + zt_err.message); } }
为什么并行快？串行是 4 + 3 = 7 秒，并行只要 max(4, 3) = 4 秒，因为两个任务同时在进行。
2-3三种写法的区别
写法特点
回调（callback）嵌套多了就是"回调地狱"，错误要靠每个回调自己判断
Promise + then用 .then().catch() 链式调用，比嵌套清晰，但步骤多时链很长
async / await像写同步代码一样写异步，用 try/catch 抓错误；并行用 Promise.all
