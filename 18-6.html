18-6 Mermaid 图表 · 智能客服系统流程图与 ER 图

姓名：张涛  |  学号：24001010104  |  《高级网页设计I》

使用 Mermaid 10.9.1 用纯文本语法绘制智能客服系统的两张图： ① 业务流程图（flowchart）——从用户提问到意图识别、知识检索、RAG 生成、转人工与知识迭代的完整闭环； ② 实体关系图（erDiagram）——用户、会话、消息、知识条目、工单、坐席六张数据表的字段与关系。 Mermaid 库已下载到本地 cdn/mermaid.min.js，无需联网即可渲染。

一、智能客服业务流程图（flowchart）
用户提问 → 意图识别 → 知识检索 → RAG 回答 / 转人工 → 评估迭代
flowchart TD
    A([用户提问]) --> B[接入网关<br/>会话创建 · 鉴权]
    B --> C{NLU 意图识别}
    C -->|闲聊 / 打招呼| D[闲聊应答模板]
    C -->|业务咨询| E[对话管理 DM<br/>上下文与槽位填充]
    E --> F[知识检索<br/>向量召回 + 关键词召回]
    F --> G{召回结果<br/>是否足够}
    G -->|足够| H[LLM 生成回答<br/>RAG · 附带知识来源]
    G -->|不足| I[兜底转人工坐席]
    D --> J[返回用户]
    H --> J
    I --> J
    J --> K[满意度评价<br/>解决率 · 转人工率]
    K --> L[(日志与评估数据)]
    L --> M[知识库更新<br/>坏例挖掘 · 文档补充]
    M --> F

流程说明：意图识别把问题分流到闲聊或业务咨询；业务咨询走“检索 + 生成”的 RAG 路线， 召回不足时兜底转人工；会话结束后的评价数据沉淀为日志，用于知识库迭代，形成闭环。

二、数据库实体关系图（erDiagram）
智能客服系统核心数据表及其关系（1 : N）
erDiagram
    USER ||--o{ SESSION : "发起会话"
    SESSION ||--o{ MESSAGE : "包含消息"
    MESSAGE }o--o| KNOWLEDGE : "引用知识"
    USER ||--o{ TICKET : "提交工单"
    AGENT ||--o{ TICKET : "处理工单"
    TICKET ||--o| SESSION : "来源于会话"

    USER {
        string user_id PK "用户编号"
        string nickname "昵称"
        string phone "手机号"
        string channel "来源渠道"
        datetime created_at "注册时间"
    }
    SESSION {
        string session_id PK "会话编号"
        string user_id FK "所属用户"
        string status "状态：进行中/结束"
        datetime start_time "开始时间"
        int round_count "对话轮次"
    }
    MESSAGE {
        string msg_id PK "消息编号"
        string session_id FK "所属会话"
        string role "角色：用户/机器人/坐席"
        text content "消息内容"
        datetime send_time "发送时间"
    }
    KNOWLEDGE {
        string kb_id PK "知识编号"
        string question "标准问题"
        text answer "标准答案"
        string category "分类：物流/售后/产品"
        vector embedding "向量表示"
        int hit_count "命中次数"
    }
    TICKET {
        string ticket_id PK "工单编号"
        string user_id FK "提交用户"
        string agent_id FK "处理坐席"
        string session_id FK "关联会话"
        string priority "优先级"
        string status "状态：待处理/处理中/已完成"
    }
    AGENT {
        string agent_id PK "坐席编号"
        string name "姓名"
        string team "所属班组"
        int workload "当前接待量"
    }

关系说明：一个用户可发起多次会话（1:N），一次会话包含多条消息（1:N）， 一条消息可引用一条知识（N:1）；用户提交工单、坐席处理工单，工单可回溯来源会话。 知识条目中的 embedding 字段存放向量，用于语义召回。

2流程图语法要点

erDiagram USER ||--o{ SESSION : "发起会话" // || 一端，o{ 多端 USER { // 实体字段表 string user_id PK "用户编号" // PK 主键 / FK 外键 string nickname "昵称" // 引号内为注释 }
四、知识点小结
文本即图表

Mermaid 把结构化文本编译成 SVG，图与代码同一份文件，便于版本管理和文档同步更新。

节点形状

[] 矩形、() 圆角、([]) 胶囊、{} 菱形判断、[()] 数据库，形状本身即语义。

关系基数

ER 图中 || 表示“恰好一个”，o{ 表示“零到多个”，组合即可表达 1:1、1:N、N:M。

本地化部署

把 mermaid.min.js 下载到 cdn 目录，用相对路径引入，离线也能渲染，避免依赖外网 CDN。
